# Альбомы сторис на teamgram: правка iOS

Сервер: divo-server MR !3 (ветка `feature/stories-gaps-albums`), поверх MR !1.
Связанный документ: [teamgram-layer201.md](teamgram-layer201.md).

## Что сделал сервер

Слой по-прежнему 201. Альбомы (layer 222) сервер принимает как **расширение** к 201 — в тех же
конструкторах, что шлёт форк:

| Метод / тип | Конструктор | Было на сервере | Стало |
| --- | --- | --- | --- |
| `stories.getAlbums` | `25b3eac7` | заглушка, всегда `albumsNotModified` | настоящий список |
| `stories.createAlbum` | `a36396e5` | дропался | работает |
| `stories.updateAlbum` | `5e5259b6` | дропался | работает |
| `stories.deleteAlbum` | `8d3456d0` | дропался | работает |
| `stories.reorderAlbums` | `8535fbd9` | дропался | работает |
| `stories.getAlbumStories` | `ac806d61` | дропался | работает |
| `stories.sendStory` (222, с `albums`) | `737fc2ec` | дропался | работает |
| `storyAlbum` / `stories.albums` | `9325705a` / `c3987a3a` | — | отдаются в 222-формате |

Для этих методов **никаких 201-обёрток не нужно**: форк уже кодирует их ровно так, как сервер
теперь ждёт, и уже умеет парсить `storyAlbum` и `stories.albums`.

## Единственная правка: `sendStory` с альбомами (сделано)

Ветка `feature/story-albums-send-story`. Раньше `TelegramCore/Sources/TelegramEngine/Messages/Stories.swift`
всегда звал `Api.functions.stories.sendStory_teamgram_layer201(...)`: обёртка шлёт 201-конструктор
`e4e6694b`, снимает бит `flags.8` и **выбрасывает `albums`** — сторис публиковалась, но в выбранный
альбом не попадала.

Теперь, если альбомы выбраны, уходит стоковый 222-метод `Api.functions.stories.sendStory(...)`
(`737fc2ec`, бит `flags.8` уже выставлен при `!folders.isEmpty`); без альбомов — прежняя
обёртка. Комментарий у `sendStory_teamgram_layer201` в `ApiTeamgramLayer200.swift` обновлён.

### Порядок выкатки

Сначала сервер (MR !3 + миграция `migrate-20261001.sql`), потом клиент. Клиент с правкой на старом
сервере потеряет **только** публикацию сторис с выбранным альбомом (`737fc2ec` будет дропнут,
«Uploading…» повиснет); публикация без альбома работает как раньше.

## Что ещё учесть

- **Принадлежность сторис к альбомам в `storyItem` сервер не отдаёт.** Поле `albums`
  (`flags.19`) есть только в 222-конструкторе `storyItem#edf164f1`, а Android на 201 его не разберёт.
  Сервер отдаёт 201-й `storyItem#79b26a24` (у форка alias). Состав альбома — через
  `stories.getAlbumStories`; галочки «в каких альбомах эта сторис» при редактировании из
  `storyItem` не заполнятся.
- **Обложка альбома** — медиа первой видимой сторис альбома (`icon_photo` для фото,
  `icon_video` для видео). У пустого альбома обложки нет.
- **Чужие альбомы**: видны только альбомы, в которых есть сторис, доступные смотрящему по
  приватности (активные или сохранённые в профиль). Альбомы каналов не поддерживаются:
  `getAlbums` для канала отдаёт пустой список, запись — `PEER_ID_INVALID`.
- **Лимиты сервера**: 100 альбомов, 1000 сторис в альбоме, название до 64 символов.
  Ошибки: `ALBUM_ID_INVALID`, `ALBUM_TITLE_INVALID`, `ALBUMS_TOO_MANY`,
  `ALBUM_STORIES_TOO_MANY`, `STORY_ID_INVALID`.
- **Обложки парсятся без alias**: сервер кодирует `Photo`/`Document` 201-конструкторами
  `photo#fb197a65` и `document#8fd4c4d8` — у форка это те же конструкторы.

## Остальное из MR !3 — без правок на клиенте

Работает со стоковыми вызовами (конструкторы 201 и 222 совпадают): списки просмотров и реакций
(фильтры, поиск, репосты, пагинация), закрепление сверху профиля (`togglePinnedToTop`,
`pinned_to_top` в `getPinnedStories`), поиск `stories.searchPosts` по хэштегу/месту, области
(`media_areas`) и репосты в `sendStory`, исправленный `editStory` (раньше правка одной подписи
сбрасывала приватность).
