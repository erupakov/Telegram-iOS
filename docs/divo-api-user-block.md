# Блокировка пользователей: API для клиентов iOS и Android

> Копия `docs/api-user-block.md` из app-backend (ветка `stage`, коммит `93fbd3c`). Актуальная версия — там.

Как вызывать `POST /api/user/block`, `POST /api/user/unblock`, `POST /api/user/blocked` и что после блокировки отдают остальные эндпоинты. Описание соответствует ветке `stage`.

## Общие правила запросов

Все три метода требуют авторизации и проходят через те же middleware, что и остальной API.

| Заголовок | Обязателен | Значение |
| --- | --- | --- |
| `Authorization` | да | `Bearer <accessToken>` — **собственный токен пользователя**. Зашитый в приложение токен агентства не подходит: заблокирует от имени агентства. |
| `Accept` | да | `application/json` |
| `App-Platform` | да | `ios` или `android`. Без него или с другим значением — 422. |
| `App-Version` | да | Строка версии, номер сборки в скобках: `1.4.0 (123)`. |
| `Accept-Language` | нет | `ru`, `en` и т. д. — язык текста в `message`. |
| `Content-Timezone` | нет | Часовой пояс клиента, например `Europe/Moscow`. |

Тело — JSON (`Content-Type: application/json`). Все три метода — **POST**, в том числе получение списка.

Каждый ответ обёрнут в конверт:

```json
{
  "message": "текст или null",
  "data": { },
  "errors": null
}
```

- `message` — текст для пользователя, локализован по `Accept-Language`.
- `data` — полезная нагрузка, у `block`/`unblock` всегда `null`.
- `errors` — `null` или объект `{ "поле": ["текст", …] }` при ошибке валидации (422). **Это никогда не строка.**

Решение принимайте по **HTTP-коду**, а не по тексту `message`: тексты переводятся и могут меняться.

Идентификатор пользователя везде — **id пользователя DIVO** (`users.id`, поле `id` в профиле), не id в teamgram и не `models.id`.

## POST /api/user/block

Блокирует пользователя от имени текущего.

### Тело

```json
{ "userId": 42 }
```

| Поле | Тип | Обязательно | Описание |
| --- | --- | --- | --- |
| `userId` | integer | да | id пользователя DIVO, которого блокируем. Принимается и `user_id`. |

### Успех: 200

```json
{ "message": "Пользователь заблокирован", "data": null, "errors": null }
```

Метод **идемпотентен**: повторная блокировка того же пользователя снова отвечает 200 и ничего не дублирует. Поэтому его безопасно повторять при сетевой ошибке и из очереди офлайн-действий.

### Что делает сервер

1. Записывает блок.
2. Делает **взаимную отписку**: текущий отписывается от заблокированного и наоборот.
3. Синхронизирует блок в teamgram: заблокированный больше не может писать в чат. Его сообщения не доставляются, сам он об этом не узнаёт.
4. **Заблокированному ничего не отправляется**: ни push, ни системного сообщения.

Синхронизация с teamgram выполняется в лучшем случае. Если у одного из пользователей нет связки с teamgram или teamgram недоступен, блок в DIVO всё равно сохраняется, и ответ всё равно 200. Ошибка уходит в логи сервера.

### Ошибки

| Код | Когда | `message` (ru) |
| --- | --- | --- |
| 400 | Нет `userId` / `user_id` | `Server Error` — текст бесполезен, это ошибка клиента |
| 401 | Нет токена или токен недействителен | — |
| 404 | Пользователя с таким id нет | `User not found` |
| 422 | Попытка заблокировать себя | «Вы не можете заблокировать себя» |
| 422 | Пользователь удалён или деактивирован | `Active user with this email does not exist` (текст про email — исторический, смысл «пользователь неактивен») |
| 422 | Профиль **текущего** пользователя деактивирован | текст `user.exceptions.profile_inactive`; токен при этом отзывается — нужно разлогинить |
| 426 | Не настроена версия приложения на сервере | `Your app version is out of date` |

## POST /api/user/unblock

Снимает блок, поставленный текущим пользователем.

### Тело

```json
{ "userId": 42 }
```

`userId` (или `user_id`) — id пользователя DIVO.

### Успех: 200

```json
{ "message": "Пользователь разблокирован", "data": null, "errors": null }
```

- Тоже **идемпотентен**: разблокировка пользователя, который не заблокирован, отвечает 200.
- Работает и для **удалённых** пользователей, чтобы их можно было убрать из списка заблокированных.
- Снимается только блок, поставленный **текущим** пользователем. Если второй пользователь тоже заблокировал текущего, его блок остаётся, и профиль по-прежнему недоступен.
- **Подписки не восстанавливаются.** После разблокировки кнопка должна снова показывать «Подписаться».
- Блок в teamgram снимается так же, в лучшем случае.

### Ошибки

| Код | Когда |
| --- | --- |
| 400 | Нет `userId` / `user_id` |
| 401 | Нет токена |
| 404 | Пользователя с таким id нет совсем |

## POST /api/user/blocked

Список пользователей, которых заблокировал текущий. Это экран **Settings → Blocked accounts**.

### Тело

```json
{ "offset": 0, "limit": 20 }
```

| Поле | Тип | Обязательно | По умолчанию | Описание |
| --- | --- | --- | --- | --- |
| `offset` | integer | нет | `0` | Сколько записей пропустить |
| `limit` | integer | нет | `20` | Размер страницы, **от 1 до 100**; больше 100 — 422 |

### Успех: 200

```json
{
  "message": null,
  "data": {
    "items": [
      {
        "id": 42,
        "fullName": "Анна Иванова",
        "role": "model",
        "roleLabel": "Модель",
        "photo": {
          "photo_id": 1001,
          "fileName": "photo.jpg",
          "fullUrl": "https://…",
          "extension": "jpg",
          "fileUuid": "…"
        },
        "avatar": { "photo_id": 1002, "fileName": "…", "fullUrl": "https://…", "extension": "jpg", "fileUuid": "…" }
      }
    ],
    "pagination": {
      "meta": { "limit": 20, "currentOffset": 1, "totalCount": 1 }
    }
  },
  "errors": null
}
```

- Порядок — **сначала последние заблокированные**.
- `photo` и `avatar` могут быть `null`. `avatar` уже содержит подстановку: если аватара нет, там фото, а у сотрудника агентства — фото агентства. Для строки списка используйте `avatar ?? photo`.
- `pagination.meta.totalCount` — общее число заблокированных, на него можно полагаться. `currentOffset` = `offset` + число элементов на этой странице: его и передавайте как следующий `offset`. Список закончился, когда `currentOffset >= totalCount`.
- В список попадают и **удалённые** пользователи. Отдельного признака у них нет. Показывайте их как обычно, `unblock` для них работает.
- Здесь только те, кого заблокировал **сам** пользователь. Кто заблокировал его, клиент не узнаёт и показывать не должен.

**Источник правды для экрана заблокированных — этот метод**, а не `contacts.getBlocked` в teamgram: в teamgram блок может отсутствовать, если синхронизация не прошла.

## Сценарии на клиенте

### Блокировка из профиля
1. Показать подтверждение.
2. `POST /api/user/block` с `id` профиля.
3. При 200:
   - сбросить у профиля состояние подписки (`isFollowed = false`) и убрать пользователя из локальных списков подписок и подписчиков;
   - убрать его контент из закэшированных лент, поиска и списков;
   - закрыть открытый профиль или перерисовать его как недоступный (см. ниже).

### Блокировка из чата
В чате известен id пользователя в teamgram, а не в DIVO. Сначала получите id DIVO: `GET /api/user/by-telegram?telegramId=<id>`. Даже если профиль уже недоступен, заглушка содержит `id`. Затем вызовите `POST /api/user/block`.

**Не вызывайте `contacts.block` и `contacts.unblock` в teamgram сами.** Блок синхронизирует сервер. Ручной вызов на клиенте рассинхронизирует teamgram с DIVO: например, после разблокировки в DIVO чат останется заблокированным.

### Разблокировка
Экран Blocked accounts → `POST /api/user/unblock` → убрать строку из списка. Подписку заново не ставить.

### Повторы и офлайн
Оба изменяющих метода идемпотентны. Их можно класть в очередь и повторять при 5xx и сетевых ошибках. 4xx не повторять.

## Что отдают другие эндпоинты после блокировки

Блок действует **в обе стороны**: всё ниже верно и для того, кто заблокировал, и для заблокированного.

| Где | Что вернёт сервер | Что делать клиенту |
| --- | --- | --- |
| `GET /api/user/{id}`, `GET /api/user/info?user_id=`, `GET /api/user/by-telegram` | 200 с заглушкой: `{ "id": 42, "isUnavailable": true, "message": "Профиль недоступен" }` — без имени, фото и прочих полей | Проверять `isUnavailable` **до** разбора профиля и показывать экран «Profile unavailable» |
| Галерея, публикации, каналы пользователя (`/user-gallery/list`, `/publication/list`, `/channels/list`) | 200 с пустым `items` | Показать пустое состояние |
| `GET /api/model-work-history?user_id=` | 200, `items: []` | Пустое состояние |
| Ссылка на агентство в чужой истории работы | `agencyUserId: null`, `isProfileAvailable: false` | Показывать запись без перехода в профиль |
| `GET /api/event/{id}` (кастинг заблокированного/заблокировавшего) | 404 | Как «событие не найдено» |
| `GET /api/feedline/{id}` | 404 | Как «запись не найдена» |
| Отклик на кастинг `POST /api/event/apply` | 422 | Сообщение из `message` |
| Лайки, избранное, подписка, эмодзи профиля (`/feedline/like`, `/publication/like`, `/user-gallery/like`, `/user/like`, `/event/{id}/like`, `/event/{id}/set-favourite`, `/favorite/mark`, `/follower/follow`, `/user/set-profile-emoji`) | 422 «Действие недоступно» | Откатить оптимистичное обновление UI. Ранее поставленный лайк контента снять можно, а лайк профиля (`/user/unlike`) — нет, тоже 422. |
| `GET /api/user/engagement?userId=` | 422 | Не показывать статистику |
| Ленты и поиск (`/feedline/list`, `/feedline/search`, `/event/list`, `/radar/models`, `/agency/search`, ростер агентства, Face Match `/fr/*`) | Пользователь и его контент просто отсутствуют | Ничего; локальные кэши после блокировки почистить самим |
| Чат (teamgram) | Сообщения заблокированного не доставляются, отправитель не получает ошибку | Ничего |
| Истории (teamgram) | Заблокированный не видит истории заблокировавшего | Ничего |

Код 422 «Действие недоступно» не выдаёт, кто кого заблокировал. Не пытайтесь это вычислять и не показывайте заблокированному, что его заблокировали.

## Чего в API нет

- Признака «меня заблокировали» нет намеренно.
- Нет отдельного метода «заблокирован ли пользователь X»: смотрите `isUnavailable` в профиле или ищите id в `/user/blocked`.
- Нет причин и комментариев к блокировке.
